# DeCaSh — Decentralized Car Sharing

Privacy-preserving rental access using zero-knowledge proofs on Ethereum. A renter proves they hold a valid booking to a car's on-board computer without revealing their secret — the car verifies the ZK proof on-chain via a Groth16 verifier contract.

## How It Works

Three actors interact with the system:

1. **Owner** — deploys the `Groth16Verifier` and `RentalCar` contracts to the chain.
2. **Renter** — generates a random secret, computes `commitment = Poseidon(secret)`, stores the commitment on-chain by calling `rentCar`, and generates a ZK proof of knowledge.
3. **Car** — calls `verifyAccess` on the `RentalCar` contract with the renter's proof. The contract checks the booking window is still active and delegates cryptographic verification to the `Groth16Verifier`.

The `bookingCommitment` stored on-chain is the sole ZK public input — the verifier only checks that the prover knows the secret behind the commitment. No identity is ever revealed.

## Architecture

```
circuits/
  ProofValidKey.circom     # Circom 2 circuit: commitment === Poseidon(secret)
  rental.zkey              # Groth16 proving key (from trusted setup)
  verification_key.json    # Verification key (for off-chain sanity checks)

contracts/
  Verifier.sol             # Groth16 verifier — generated by snarkjs, deployed once
  RentalCar.sol            # Booking logic + on-chain proof verification

scripts/
  Owner.js                 # Deploys contracts, writes scripts/config.js
  Renter.js                # Books car, generates ZK proof → scripts/proof.json
  Car.js                   # Submits proof to contract, prints access result
```

## Prerequisites

- Node.js ≥ 18
- [circom](https://docs.circom.io/getting-started/installation/) v2 (install via `cargo install circom`)
- Hardhat (installed via npm)

## Setup

```bash
npm install
npx hardhat compile
```

## Running

### 1. Start a local Ethereum node

```bash
npx hardhat node
```

### 2. Deploy contracts (Owner)

```bash
node scripts/Owner.js
```

Deploys `Groth16Verifier` and `RentalCar`, then writes `scripts/config.js` with the deployed addresses.

### 3. Book the car and generate a proof (Renter)

```bash
node scripts/Renter.js
```

- Generates a random 256-bit secret
- Computes `commitment = Poseidon(secret)`
- Calls `rentCar(hoursToRent, commitment)` on-chain
- Produces a Groth16 ZK proof via snarkjs
- Saves `pA`, `pB`, `pC` to `scripts/proof.json`

### 4. Verify access (Car)

```bash
node scripts/Car.js
```

Reads `scripts/proof.json` and calls `verifyAccess(pA, pB, pC)` on the contract. The contract checks the booking is still within its time window and verifies the proof against the stored commitment.

## ZK Circuit Workflow

If you change the circuit, regenerate all artifacts:

```bash
cd circuits

# 1. Compile
circom ProofValidKey.circom -l ../node_modules --r1cs --wasm --sym

# 2. Trusted setup
snarkjs powersoftau new bn128 12 pot12_0000.ptau
snarkjs powersoftau contribute pot12_0000.ptau pot12_0001.ptau
snarkjs powersoftau prepare phase2 pot12_0001.ptau pot12_final.ptau
snarkjs groth16 setup ProofValidKey.r1cs pot12_final.ptau circuit_0000.zkey
snarkjs zkey contribute circuit_0000.zkey rental.zkey

# 3. Export verification key and Solidity verifier
snarkjs zkey export verificationkey rental.zkey verification_key.json
snarkjs zkey export solidityverifier rental.zkey ../contracts/Verifier.sol

# 4. Recompile contracts
cd ..
npx hardhat compile
```

## Key Design Decisions

- **Secret stays with the renter.** The owner never sees it. The commitment (a Poseidon hash) is all that goes on-chain.
- **Verifier is deployed once.** `Groth16Verifier` is circuit-specific but does not change per rental — only the commitment changes.
- **No identity revealed.** The ZK proof only asserts knowledge of the preimage of the stored commitment, not who the renter is.
- **Time-bounded access.** `verifyAccess` rejects proofs outside the booked `[startTime, endTime]` window.

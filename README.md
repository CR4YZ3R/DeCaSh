# DeCaSh — Decentralized Car Sharing

Privacy-preserving rental access using zero-knowledge proofs on Ethereum. A renter proves they hold a valid booking to a car's on-board computer without revealing their secret — the car verifies the ZK proof on-chain via a Groth16 verifier contract. This inherently links the customer's payment to his/her provided commitment holding some form of a "lock" for the car. 

## How It Works

Three actors interact with the system:

1. **Owner** — deploys the `Groth16Verifier` and `RentalCar` contracts to the chain.
2. **Renter** — generates a random secret, computes `commitment = Poseidon(secret)`, stores the commitment on-chain by calling `rentCar`, and generates a ZK proof of knowledge. To additionally ensure, authenticity of the proof, the proof is signed by the renter.
3. **Car** — calls `verifyAccess` on the `RentalCar` contract with the renter's proof. The contract checks the booking window is still active and delegates cryptographic verification to the `Groth16Verifier`.

The `bookingCommitment` stored on-chain is the sole ZK public input — the verifier only checks that the prover knows the secret behind the commitment. No identity is ever revealed.

## Architecture

```
circuits/
  ProofValidKey.circom     # Circom 2 circuit: commitment === Poseidon(secret)
  rental.zkey              # Groth16 proving key (from trusted setup)
  verification_key.json    # Verification key (for off-chain sanity checks)
  ...

contracts/
  Verifier.sol             # Groth16 verifier — generated by snarkjs, deployed once
  RentalCar.sol            # Booking logic + on-chain proof verification

scripts/
  Owner.js                 # Deploys contracts, writes scripts/config.js
  Renter.js                # Books car, generates ZK proof → scripts/proof.json
  Car.js                   # Submits proof to contract, prints access result
```

## Prerequisites

- Node.js ≥ 18
- Hardhat (installed via npm)

## Setup

```bash
npm install
npx hardhat compile
```

## Running

### 1. Start a local Ethereum node

```bash
npx hardhat node
```

### 2. Deploy contracts (Owner)

```bash
node scripts/Owner.js
```

Deploys `Groth16Verifier` and `RentalCar`, then writes `scripts/config.js` with the deployed addresses.

### 3. Book the car and generate a proof (Renter)

```bash
node scripts/Renter.js
```

- Generates a random 256-bit secret
- Computes `commitment = Poseidon(secret)`
- Calls `rentCar(hoursToRent, commitment)` on-chain
- Produces a Groth16 ZK proof via snarkjs
- Saves `pA`, `pB`, `pC` and a signature to `scripts/proof.json`

### 4. Verify access (Car)

```bash
node scripts/Car.js
```

Reads `scripts/proof.json` and calls `verifyAccess(pA, pB, pC)` on the contract. The contract checks the booking is still within its time window and verifies the proof against the stored commitment and the validity of the signature.

## Key Design Decisions

- **Secret stays with the renter.** The owner never sees it. The commitment (a Poseidon hash) is all that goes on-chain.
- **Verifier is deployed once.** `Groth16Verifier` is circuit-specific but does not change per rental — only the commitment changes.
- **Time-bounded access.** `verifyAccess` rejects proofs outside the booked `[startTime, endTime]` window.
- **Early returns.** Renters can return the car early (via `returnCarEarly`) and get some of their remaining time refunded (but they will still pay the remaining hour). This incentivises customers to return the car earlier, if they do not require the full booking time.
- **Owner controls availability.** `setBookingInactive` can be used to activate/deactivate the booking mechanics. The current user will be able to use their remaining booked time but *no new* bookings can be made. This way the owner can deactivate booking for the car. We added this functionality, so that owners can effectively deactivate the booking services. This inactive period can then be used to peform maintanance on the car or permanently disable the smart contract.
- **Safe payouts.** `payoutOwner` allows the owner to pay out the unrefundable money. It is important that the contract does not allow to pay out money, that is not yet used up by the renter. This way, the renter is able to still return the car early whenever they chose to, while the owner will be paid out the maximum available funds.
